# SnapWheel 版本记录

## 约定
- 每个版本一个文件夹：`versions\v<版本号>\`
- 每个版本文件夹里包含：
  - `SnapWheel.exe` —— 该版本的可执行文件
  - `SnapWheel.cs` —— 该版本的完整源码
  - `snapwheel.ico` —— 图标（打包用）
  - `NOTES.md` —— 该版本更新说明
- 版本号写在源码的 `AppInfo.Version` 里，和文件夹名保持一致。

## 版本线（重要）
同一份源码用编译开关产出两条线：

| 版本线 | 编译方式 | 含义 |
|---|---|---|
| **v0.2.x** | `csc /define:NO_KEY` | **没有万能键**，但有框选缩放 + 比例锁定 + 多 Wheel |
| **v0.3.x** | 普通编译 | **完整版**，额外含**万能键（摇杆圆盘）** |

## 当前版本
**v0.4.8**（含"圆盘动作名改完不变"的修复 + 帧耗时统计 + 行为测试）。
源码与 `build\` 产物在仓库根目录（git 提交 58cee15）；桌面分发版 / 分发 zip 每次发布时再更新。
⚠️ `versions\v0.4.8\` 里那份快照是当天早些时候的构建，不含这次修复（历史归档不改，见其 NOTES.md）。

## 记录新版本
在 `<项目目录>` 下运行：

```powershell
# 用源码里现有版本号快照（会编译 + 归档 exe/源码/图标 + 写 NOTES + 更新本表）
powershell -ExecutionPolicy Bypass -File .\record-version.ps1 -Note "本次改了什么"

# 或换版本号（会改源码版本号并重新编译）
powershell -ExecutionPolicy Bypass -File .\record-version.ps1 -Version 0.3.2 -Note "新增 XX"
```

也可以直接跟我说“记录一个新版本”，我来改版本号、编译两条线、快照、写说明。
