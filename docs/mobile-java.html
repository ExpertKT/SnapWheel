从一个小程序学 Java

手机离线版 ｜ 写给刚接触编程的你 ｜ 不需要任何基础

这是一个真实的小程序，叫 SnapWheel：Windows 上截图用的工具。截完图不用保存，图会直接变成屏幕角上的一张小卡片，要用的时候把它拖进聊天窗口就发出去了。

它不是 Java 写的（是 C#），但 C# 和 Java 长得非常像 —— 像到你可以把它的代码当成"另一个方言的 Java"来读。

这本册子做的事：借这个真实项目，把 Java 里那些抽象的概念讲成你能看懂的东西。

1 · 先看懂几个词

后面会一直用到，先花两分钟认识它们。看不懂没关系，往下读，看到例子就懂了。

词大白话生活类比
类 (class)一张"设计图"，规定了某种东西长什么样、能做什么"户型图"
对象 (object)按那张图造出来的一个具体东西按户型图盖出的"一套房"
方法 (method)这个东西会做的一件事"开灯"这个动作
属性/字段这个东西身上记着的信息房子的"面积、楼层"
继承在别人的设计图上加点新东西，不用从头画在"住宅图"上改出"带车库的住宅"
接口一份"承诺清单"：说好要实现哪几件事，但不管你怎么做"能开"这个承诺：汽车、门、罐头都承诺，但方式各不同
异常程序运行中出的岔子，可以被"接住"处理做饭糊了 → 有应对方案，而不是整桌报废
GC（垃圾回收）程序用过的内存，系统自动帮你清理，不用手动释放餐厅有服务员收盘子，不用自己洗
编译把写好的代码"翻译"成机器能跑的形式把菜谱翻译成厨师看得懂的标准单
调试程序不对时，一步步找出哪里错了菜太咸 → 逐项排查是盐、酱油还是高汤

2 · C# 和 Java 是什么关系

一句话：它们是两家公司做的、思路几乎一样的两种语言。

类比：Java 和 C# 就像"同一套教学大纲下、两所学校出的教材" —— 章节顺序、知识点几乎一样，只是用词和个别写法有差别。学会一个，另一个能直接看懂七八成。

它们的共同点（这些也是 Java 的核心特征）：

  • 都是静态类型：写代码时就要说清"这个变量装的是整数还是文字"；
  • 都是面向对象：程序由"类"和"对象"搭起来；
  • 都有垃圾回收：不用手动管内存；
  • 都跑在虚拟机上（Java 是 JVM，C# 是 .NET 的运行时）—— 所以"写一次，很多地方能跑"。

同一个东西，两种写法

下面左边是这个项目的写法（C#），右边是 Java 的等价写法。你会发现它们几乎一模一样：

想做的事C#（项目里）Java
定义一个东西class Pic { }class Pic { } ✅ 一样
继承class A : B { }class A extends B { } ⚠️ 符号不同
实现接口class A : IFace { }class A implements IFace { } ⚠️
打印一行Console.WriteLine("hi");System.out.println("hi"); ⚠️
一个列表List<int> a = new List<int>();List<Integer> a = new ArrayList<>(); ⚠️ 类型写法不同
接住异常try { } catch (Exception e) { }try { } catch (Exception e) { } ✅ 一样
遍历foreach (var x in list) { }for (var x : list) { } ⚠️
字符串拼接$"共 {n} 张""共 " + n + " 张" ⚠️
记住这个感觉：你以后看到 C# 代码时的"读法"，就是把 extends 换成 :、把 System.out.println 换成 Console.WriteLine。剩下 90% 是相通的。

3 · 从项目里看六个概念

1类与对象：一张图 vs 一套房

项目里有一张"图片"的概念。它的设计图大致是这样（我简化了）：

class StoreItem        // 设计图：一张图该有什么
{
    public Bitmap Image;      // 属性：图本身
    public string Name;       // 属性：名字
    public int Index;         // 属性：它在环上是第几张

    public void Save(string path)   // 方法：能被要求做的事
    {
        // ...把图存到硬盘...
    }
}

而"一套房"是这样造出来的：

StoreItem a = new StoreItem();   // 造出第一张
StoreItem b = new StoreItem();   // 造出第二张
类比：class 是户型图，new 是按图盖房。图纸只有一张，房子可以盖很多套 —— 而且每套房的装修（属性值）可以不同。
2方法：对象"会做的事" 
a.Save("C:/图片/1.png");

读法："让 a 这个东西，去做 Save 这件事，材料是那个路径"。

类比：方法是"动词"。小狗.叫()、小狗.吃(骨头) —— 点在前面的是"谁"，括号里的是"给它什么"。

Java 写法完全一样：a.save("...");

3继承：在别人的图上改，不用从头画 
class OverlayForm : Form     // C#：截图窗口是一种"窗体"
{
    // 它自动拥有 Form 的全部能力：能显示、能接收鼠标键盘
    // 这里只写"它多出来的部分"
}
类比：Form 是"通用房子图纸"（有门有窗有墙），OverlayForm 是在它基础上加了"整面墙都是玻璃"的改造版。不用重新画门窗。

Java 里写成 class OverlayForm extends JFrame。

4接口：一份"承诺清单" 
interface IMessageFilter        // 承诺：我能"过滤消息"
{
    bool PreFilterMessage(ref Message m);   // 具体怎么做，你自己定
}

项目里有个窗口声明"我实现这份承诺"，于是系统就会把消息先交给它过一遍。

类比：接口像"面试要求：必须会开车"。它不教你怎么开，只要求你会开 —— 至于你开的是轿车还是卡车，它不管。

Java 里写成 class X implements IMessageFilter。

5异常：出岔子时别让整桌菜报废 
try
{
    bmp.Save(path);              // 可能会失败（磁盘满、路径不对）
}
catch (Exception ex)
{
    MessageBox.Show("保存失败：" + ex.Message);   // 接住它，告诉用户
}
类比：try 是"我打算做这道菜"，catch 是"如果糊了就这样补救"。关键是：出岔子不等于程序崩溃。

Java 一模一样。**Java 还多一层要求**：有些异常你必须显式处理（叫"受检异常"），编译器会提醒你 —— 这是 Java 比 C# 更严格的地方。

6集合：一组东西，而不是一个 
List<StoreItem> items = new List<StoreItem>();
items.Add(第一张);
items.Add(第二张);
类比：数组像"固定 10 个格子的药盒"，列表像"可以随时加格子的收纳架"。

Java 里最常用的是 ArrayList（写法略有不同，意思一样）。项目里几乎所有"一堆东西"都是列表。

4 · 五个能直接学走的故事

这些都是这个项目开发过程中真实发生的事。你不需要会写代码，也能从里面学到东西 —— 而且这些道理在 Java 里一模一样适用。

1「先量一量，再动手」—— 猜了三次都没对

项目里有个动画很卡。开发者凭经验猜：可能是"每帧重画了整张屏幕"，于是改了一处；还是卡，又猜了第二个原因，改了第二处；第三次还是卡。

后来他决定先测量：给程序加上计时，看看每一帧到底花在哪。结果发现 ——

  • 他以为的"元凶"，实测只占 0.3 毫秒（几乎可以忽略）；
  • 真正的大头在别处，占了 22 毫秒；
  • 再细分下去，又发现真正的大头是"每帧都在重新计算布局"。
能学走的：遇到"为什么这么慢"，先量，再改。凭感觉猜，往往改半天改错地方。
Java 里也一样：程序慢的时候，先用工具（如 JProfiler、VisualVM）看看到底是谁慢，而不是猜。
2「说好一起做的事，两边的标准得一样」

项目要把一段字画在图上，需要先问"这段字有多宽"，好给它留位置。开发者用了一个方法去量，却用了另一种方式去画 —— 结果量出来 100 像素，实际画出来 118 像素，字被裁掉了半截。

同一个错误，他在项目里犯了四次（字体不同、量的方式不同、对齐基准不同…）。

类比：你要裁一块布，先用市尺量，却拿英寸的尺子去剪 —— 长度一定对不上。
量的时候用哪把尺，裁的时候就得用哪把。
能学走的：很多 bug 不是"写错了"，而是"两边约定不一致"。更好的做法是：把这四件事（量的方式、画的字体、对齐基准、单位）打包成一个函数，让调用的人没法写错 —— 好的设计能让错误写不出来。
3「复制」和「移动」不是一回事

用户把一张图从环上拖到聊天窗口，图就发过去了。但开发者发现：拖完之后，环上那张图也没了，想再发给别人就没有了。

原因：这个"拖"在系统里是复制的意思（对方拿到的是副本），但代码却在成功之后把原件删了 —— 把"复制"当成了"移动"。

能学走的：写代码前先问自己一句："这个动作是复制、还是移动？谁拥有这份数据？" 想清楚再写，比写完再 debug 便宜得多。
4「用的时候先记账，用完再还」—— 嵌套时容易丢

项目有个"总在最前面"的功能。打开设置窗口时，主窗口要让到后面去；关掉设置，主窗口再回到最前面。

原来的实现方式：关之前先记住"我在最前面"，让位；结束时恢复成记住的那个值。

看起来很对，但出问题了：如果"让位"期间又发生了一次让位（比如截图时又打开了设置），恢复出来的就是"后面的状态"，于是主窗口永远回不到最前面了。

正确做法：用计数 —— 第一个进来的人负责保存原状态，最后一个离开的人负责恢复。中间的人只是加减一个数字。
这个套路在 Java 里到处都是：数据库连接池、锁、事务，都是"谁先来谁负责、谁最后走谁收尾"。
5「中文说得好好的，换成英文就挤爆了」

项目原本只有中文界面。想加英文时发现：所有按钮和文字都被裁掉了、互相压在一起。

因为当初排版是按"中文字数"估的宽度 —— 而同一句话，英文往往长得多。

类比：你按"中文 8 个字"给标签留位置，换成 "Screenshots will appear here"（30 个字符）自然放不下。
能学走的：① 宽度要实际量，不要靠数个数估；② 做界面时，一开始就用最长的语言试一遍；③ 这个道理对"多语言软件"是基本功。

5 · 这个项目是怎么组织的

一个项目变大以后，"把代码放在哪个文件里"就成了一门学问。这个项目的做法是：按"负责什么事"分文件，文件名前面加编号当作阅读顺序。

文件它负责什么Java 项目里通常对应
00-AppInfo版本号、名字常量类 / 配置文件
05-Err记录错误日志、统计性能日志工具类（Log4j / SLF4J）
10-Native所有和操作系统打交道的代码，集中一处工具类 / 适配层
25-Store管理"一堆图片"数据模型 / DAO 层
35-Settings读写设置配置类
50-OverlayForm截图界面界面类（Swing / JavaFX）
90-App程序入口含 main 方法的主类
能学走的（对 Java 特别有用）：
  • 按职责分文件，不要什么都塞一个文件；
  • 和外部世界打交道的东西集中放（文件、网络、系统调用）—— 将来换环境时只改一处；
  • 程序要能自己说出"我哪里出错了、哪里慢了" —— 这就是日志和监控，Java 项目里同样是基本功。

6 · 给你的练习建议

你刚接触编程，最好的入门方式是先做小、但完整的东西。下面按难度排，每个都能独立完成：

练习你会学到
猜数字游戏：程序想一个数，你猜，它提示"大了/小了"变量、输入输出、循环、条件判断
通讯录：能加人、按名字查、列出全部类与对象、列表（ArrayList）、遍历
记事本（存文件）：写几条，存到硬盘，下次打开还在文件读写、异常处理
给通讯录加"撤销删除"数据结构、状态管理（对应本册故事 4）
做一个能显示窗口的小程序（Swing 或 JavaFX）界面编程入门 —— 你会发现"画东西"和本册故事 2 是同一回事
三条建议：
① 不要一开始就追求"大项目" —— 先把上面的小东西做完 3 个，比读十本书有用；
② 出错时先读报错信息 —— Java 的报错信息其实写得很清楚，它会告诉你第几行、什么类型的问题；
③ 把"为什么这么写"记下来 —— 不是为了别人，是为了三个月后的你自己。

这个项目叫 SnapWheel（快照轮环），是 Windows 上的截图小工具，用 C# 写的。
本册由项目作者整理，目的是让学 Java 的人也能从这个真实项目里学到东西。
C# 和 Java 是"表兄弟" —— 你在 Java 里学到的工程思维，在这个项目里全都能看见。
