从一个小程序学 C++

手机离线版 ｜ 写给学过 C、想往 C++ 走的人 ｜ 不需要 C++ 基础

这是真实项目 SnapWheel（Windows 截图工具）：截完图不用保存，图直接变成屏幕角上的小卡片，拖进聊天窗口就发出去了。

它本体是 C# 写的。但你已经有 C 的底子，而 C++ 正好卡在 C 和 C# 中间 —— 借这个项目，你可以把三者一次看清楚：哪些是 C 就有的、哪些是 C++ 加的、哪些是 C# 又换了个做法的。

看清三者的关系，比死记 C++ 语法有用得多。

1 · C / C++ / C# 三者关系

一句话：C++ 是 C 的"带类的超集"（几乎能编译所有 C 代码）；C# 是微软参照 C++ 做的新语言，把 C++ 里最容易出事的部分（手动内存、指针、头文件）换成了自动的。
CC++C#
出身1972，系统编程C 加面向对象2000，微软，参照 C++/Java
内存malloc/freeRAII + 智能指针（仍是手动，但更安全）GC 全自动
指针到处是有，但推荐用引用和智能指针有"引用"，没有指针算术
字符串char* + 手动std::string（自动管理）string（不可变 + GC）
数组裸数组std::vector（能自动扩容）List<T>
面向对象没有有（多继承、虚函数）有（单继承 + 接口）
编译编译成机器码编译成机器码编译成中间码，运行时再编译
头文件有有（还更复杂）没有
运行速度最快最快（和 C 同级）略慢（有虚拟机）
谁在用内核、驱动、单片机游戏引擎、浏览器、数据库、交易系统Windows 应用、Unity 脚本、企业后端
记住这条主线：
C 关心机器怎么跑 → C++ 在 C 上加了一层"用对象和自动清理来管资源" → C# 把"自动"推到极致（连内存都不用管了）。
所以：从 C 学 C++，你要学的是"怎么让对象负责资源的生死"；从 C++ 看 C#，你会发现 C# 把这件事交给了 GC。

2 · 从项目代码看 C++ 的写法

左边是这个项目（C#）的真实写法，右边是 C++ 的等价写法。看懂差异，就懂了两种语言的核心取舍。

要做的事项目里（C#）C++
定义一个类class Pic { }class Pic { }; ⚠️ 结尾要 分号
声明和实现一个文件里都写通常 .h 声明 + .cpp 实现
继承class A : B { }class A : public B { }; ⚠️ 要写 public
虚函数virtual void f();（默认虚）virtual void f() override; ⚠️ 要显式 virtual
动态数组List<Pic> a = new List<Pic>();std::vector<Pic> a; ⚠️ 直接就是一个对象
字符串string s = "hi";std::string s = "hi"; ✅ 很像
自动释放using (var b = new Bitmap()) { }{ auto b = std::make_unique<Bitmap>(); } ⚠️ 作用域结束自动释放
拷贝默认传引用（不复制）⚠️ 默认会复制整个对象！要 const& 才不复制
遍历foreach (var x in list)for (const auto& x : list) ✅ 概念一样
函数对象delegate(...) { } / Lambda[&](int x) { } ✅ Lambda 就是 C++ 先有的
看这段时的重点：
① 项目里到处出现的 using (Font f = new Font(...)) { ... }，在 C++ 里叫 RAII —— 但 C++ 是靠构造函数和析构函数自动完成的，一个花括号就够，不需要 using 关键字。
② 最大的思维差异：C++ 里 Pic a = b; 是真的复制了一份，C# 里只是多了一个引用。这条不搞清楚，会写出莫名其妙的性能问题和 bug。

3 · C++ 的六个关键概念

1RAII：让对象管资源的生死（C++ 的灵魂）

名字很吓人，意思很朴素：把资源（内存、文件、锁）交给一个对象，对象一死，资源就自动释放。

{
    std::ifstream f("data.txt");   // 构造：打开文件
    // ... 用 f 读数据 ...
}                                  // 离开花括号：析构函数自动关闭文件
// 哪怕中间 throw 异常抛出去，也一样会关闭
类比：像住酒店 —— 退房时服务员自动来收拾，你不用记得"我借过毛巾要去还"。
C 里你得手动 fclose；C# 里靠 using 或 GC；C++ 靠析构函数，而且不依赖 GC。
为什么这是 C++ 最重要的东西：它是 C++ 能在"没有垃圾回收"的前提下还比较安全的原因。你看到项目里的 using (...)，就该想到"这在 C++ 里是自动的"。
2智能指针：不用 delete，也基本不会内存泄漏 
{
    auto a = std::make_unique<Pic>();   // 独占：只有一个主人
    auto b = std::make_shared<Pic>();   // 共享：引用计数（像 C# 的 GC 计数思路）
    a->save("1.png");
}   // 自动 delete，不用你写

C 里你写 malloc 就必须写 free；C++ 里你几乎可以不写 new/delete —— 交给智能指针。

类比：unique_ptr 像"唯一的钥匙"（不能复制，只能转移）；shared_ptr 像"合租登记表"（每个人走时划掉自己，最后一个走的负责锁门）。
3值语义 vs 引用语义（最容易搞混的一点） 
// C++：默认是"复制一个"
std::vector<int> a = {1,2,3};
std::vector<int> b = a;      // b 是独立的副本！改 b 不影响 a
void f(std::vector<int> v) { }        // 传参：复制一份（慢！）
void g(const std::vector<int>& v) { }  // 传引用：不复制（推荐）

而 C# 里 List a = b; 只是多了一个引用，改一个另一个也变。

能学走的：写 C++ 时，传参默认加 const&（引用且不修改）—— 这既是性能习惯，也避免了很多意外修改。
4虚函数与多态：同一个调用，不同行为 
class Shape { public: virtual void draw() = 0; };       // 接口：必须自己实现
class Circle : public Shape { public: void draw() override { /* 画圆 */ } };
class Square : public Shape { public: void draw() override { /* 画方 */ } };

std::vector<std::unique_ptr<Shape>> list;
for (auto& s : list) s->draw();    // 同一句，各画各的
类比：你喊"开动" —— 厨师去做菜、司机去开车、学生去写作业。下达的是同一个命令，执行因人而异。

C 里要实现这个，得用"函数指针放进结构体"（很像手写虚表）。C++ 把它做进了语言里。

5模板：写一次，适配任意类型 
template <typename T>
T maxOf(T a, T b) { return a > b ? a : b; }

maxOf(3, 5);          // T = int
maxOf(2.5, 1.5);      // T = double
maxOf(std::string("a"), std::string("b"));   // T = string
类比：模具 —— 换原料就能压出不同产品。编译时"按需生成"，所以比运行时泛型（C#）更快，但代码体积会变大、报错信息很长。
6移动语义：把资源"搬走"而不是"复制一份" 
std::vector<int> makeVec() {
    std::vector<int> v(1000000);
    return v;                   // 现代 C++ 会"移动"而不是复制（几乎零成本）
}
std::vector<int> w = makeVec();   // 内部指针被搬过来，不是拷贝一百万个元素
类比：复制一箱书 = 一本本抄；移动 = 直接把箱子搬走。箱子还是那个箱子，只是换了位置。

这是 C++11 之后最重要的特性之一（std::move）。C# 里没有直接对应物（有 GC，不太需要）。

4 · 五个能直接学走的故事

都是这个项目开发中真实发生的事。不用写代码也能懂，而且在 C++ 里一模一样适用。

1「先量一量，再动手」—— 猜了三次都没对

有个动画很卡。开发者凭经验猜了三次：先猜"每帧重画整屏"，改了；还卡；再猜两个原因，都改了；还是卡。

后来他决定先测量：给程序加计时，看每一帧到底花在哪。结果 ——

  • 他以为的元凶：实测只占 0.3 毫秒（可忽略）；
  • 真正的大头在别处：22 毫秒；
  • 再往下拆，真凶是一个绘图函数调用，在 2560×1440 的画布上要 9 毫秒，而同样操作在小画布上只要 0.4 毫秒 —— 相差 21 倍。
能学走的：遇到"为什么这么慢"，先量再改。靠感觉猜，往往改半天改错地方。
C++ 里工具更多（perf、VTune、-pg 采样、chrono 计时），没有理由靠猜。
2「说好一起做的事，两边标准得一样」

要把文字画到图上，得先问"这段字有多宽"好给它留位置。开发者用一种方式去量，却用另一种方式去画 —— 量出 100 像素、实际画出 118 像素，字被裁掉半截。

同一个错误，他犯了四次（字体不同、度量方式不同、对齐基准不同、甚至两套绘图 API 混用）。

类比：裁布时用市尺量、拿英寸尺剪 —— 长度必然对不上。量用哪把尺，裁就得用哪把。
能学走的：很多 bug 不是"写错了"，而是"两边约定不一致"。更好的做法是把它封装成一个函数，让调用方没法写错 —— 好的设计能让错误写不出来。（这个项目后来真的抽了这样一层。）
3「复制」和「移动」不是一回事

用户把图从环上拖到聊天窗口，图就发出去了。但开发者发现：拖完之后环上那张也没了，想再发一次就没有了。

原因：这个"拖"在系统里是复制语义（对方拿到副本），而代码在成功之后把原件删了 —— 把复制当成了移动。

能学走的：写代码前先问"这是复制还是移动？谁拥有这份数据？"
而这条对 C++ 尤其重要：C++ 里"拷贝构造 / 移动构造"就是专门表达这件事的 —— 语义不清，就会出现"偷偷复制了 100 万条数据"或者"资源被搬走后原对象还被人用"。
4「进的时候记一笔，走的时候还一笔」—— 嵌套时容易丢

项目有"总在最前面"的功能。打开设置窗口时主窗口让位，关掉再回最前。

原实现：让位前记住"我在最前"，结束时恢复成记住的值。看着对，但——如果让位期间又发生一次让位（截图时又打开设置），恢复出来的就是"后面的状态"，主窗口永远回不到最前了。

正确做法：用计数 —— 第一个进来的人保存原状态，最后一个离开的人恢复，中间的人只加减数字。
C++ 里这个模式到处都是：shared_ptr 的引用计数、锁的嵌套管理、资源池…… 而且 C++ 的 RAII 让它写起来特别自然（进入构造 +1，析构 −1）。
5「中文排得好好的，换成英文就挤爆了」

项目原只有中文界面。加英文时发现所有文字都被裁掉、互相压在一起 —— 因为当初排版是按"中文字数"估宽度的。

类比：按"中文 8 个字"留位置，换成 "Screenshots will appear here"（30 字符）当然放不下。
能学走的：① 宽度要实际量，别数个数；② 做界面一开始就用最长的语言试；③ 放不下时，正确做法是截断加省略号，而不是压到别的控件上。

5 · C++ 特有的六个坑

这些是 C++ 独有的（C 和 C# 里没有或不一样），提前知道能省很多时间。

坑说明怎么避免
悬垂指针/引用对象已经销毁，你还拿着指向它的指针或引用去用用智能指针；不要让引用活得比对象长
默认拷贝的隐形开销void f(vector<int> v) 会复制整个 vector传参用 const&；返回时依赖移动语义
拷贝构造 / 析构不配对类里有裸指针却没写析构和拷贝构造 → 双重释放能用智能指针就别用裸指针（"三/五法则"）
未定义行为（UB）越界访问、用未初始化变量… 有时"看起来能跑"开 -Wall -Wextra，用 sanitizer（-fsanitize=address,undefined）
头文件的连锁编译改一个 .h，所有包含它的文件全部重编，越编越慢头文件只放声明；用前置声明；必要时用 PIMPL
模版报错看不懂一行错误信息可能上百行从最后一行"实际错误"开始读，再从第一行找"哪个类型不对"
和 C# 最大的心态差别：C# 里"写错了"通常是运行时抛异常（你能看见）；C++ 里"写错了"常常是"现在能跑，换个编译器/换个优化等级就崩"。所以 C++ 里 "能跑"不等于"对" —— 这就是为什么 C++ 更依赖工具（编译器警告、sanitizer、静态分析）和纪律。

给你的练习（按难度，都能独立完成）

练习你会学到
把一段 C 代码改成 C++：手写的动态数组换成 std::vector，char* 换成 std::string标准库替你做掉了哪些手工活
写一个 RAII 包装：把 fopen/fclose 包成一个类，构造开、析构关RAII 的核心（C++ 最重要的思想）
用智能指针管一个对象数组，故意让它抛异常，观察有没有泄漏智能指针为什么能免掉 delete
写一组"形状"类（圆、方），用 virtual 让它们各自算面积多态与虚函数
做一个能显示窗口的小程序（可选 SFML 或 raylib）你会发现"画东西"和故事 2 是同一回事
三条建议：
① 先把 RAII 和智能指针搞懂再往下走 —— 它们是 C++ 的地基，跳过会一直别扭；
② 永远开编译器警告（-Wall -Wextra），把警告当错误看；
③ "能跑"不等于"对" —— 多写测试、多用 sanitizer，这是 C++ 里最重要的自我保护。
