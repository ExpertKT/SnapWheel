从一个小程序学 C++

手机离线版 ｜ 写给刚开始学 C++、还不太清楚编程是怎么回事的你

这是一个真实的小程序，叫 SnapWheel：Windows 上截图用的工具。截完图不用保存，图会直接变成屏幕角上的一张小卡片，要用的时候把它拖进聊天窗口就发出去了。

它本身不是 C++ 写的（是另一种语言），但里面用到的东西，C++ 里都有 —— 而且它的代码不长、结构清楚，很适合当"看别人怎么写程序"的第一个例子。

这本册子不需要你有任何基础。每个词第一次出现时都会解释，每个概念都配一个生活里的类比。

1 · 先看懂几个词

后面会一直用到。现在看不懂没关系，往下读，看到例子就明白了 —— 不用背。

词大白话生活里的类比
程序让计算机按顺序做事的一串指令一份菜谱
代码你写下的那些指令本身菜谱上的字
变量给一个值起个名字，方便反复使用贴了标签的盒子："盐""糖"
类型说明这个盒子里装的是数字还是文字规定"这个罐子只装盐"
函数 / 方法一段可以重复使用的操作菜谱里的"炒香葱姜"
类（class）一张设计图，规定某种东西长什么样、能做什么户型图
对象照着设计图造出来的一个具体东西按户型图盖出的那套房
编译器把你写的代码翻译成计算机能直接执行的形式把菜谱翻译成厨师的标准单
头文件一个说明"有哪些现成东西可以用"的清单文件图书馆的借书目录
库别人已经写好、你可以直接拿来用的工具集合厨房里现成的料理机
报错计算机说"这里我看不懂/做不了"厨师说"这份菜谱第 3 步缺材料"
调试找出错在哪、然后修好菜太咸 → 逐项排查是盐、酱油还是高汤

2 · 学 C++ 一般会怎么开始

先说一句让你安心的：C++ 的"难"不在入门，在细节。

入门阶段你要学的其实和别的语言差不多 —— 变量、判断、循环、函数、类。这些几天就能写起来。C++ 真正复杂的地方（内存怎么管、指针怎么用、编译怎么配）是后面才需要碰的，而且现代 C++ 已经提供了更安全的写法，很多细节可以晚点再学。

所以第一阶段的正确目标：能把一段小逻辑写成能跑的程序，能看懂别人代码里的基本结构。
不要一开始就去啃指针、内存、模板这些东西 —— 那会让你以为"编程很难"，其实只是"那部分难"。

你的第一个 C++ 程序长这样

#include <iostream>      // 用到一个"能在屏幕上打印"的现成工具
using namespace std;     // 这些现成工具的名字不用每次写全

int main()               // 程序的入口：从这里开始执行
{
    cout << "你好，世界" << endl;   // 在屏幕上打印一行字
    return 0;                       // 告诉系统"正常结束了"
}

把这四行拆开看，其实只有三件事：① 声明要用什么工具 ② 写入口 ③ 做事。后面所有的程序都是这个骨架的扩展。

刚开始练的时候，只做一件事：改这个程序 —— 换文字、加一行、删一行、故意写错看看报错长什么样。
把"改一行 → 重新编译 → 看结果"这个循环练熟，比读十页语法书有用。

3 · 从项目里看六个最基础的概念

下面每段代码都是"这个项目里做过的事"改写成的 C++ 写法。都很短，每段只讲一个概念。

1变量与类型：给值起名字 
int    count = 3;            // 整数：一共有几张图
double ratio = 16.0 / 9.0;   // 小数：宽高比
string name  = "设计稿";      // 文字：这个轮盘叫什么
bool   saved = true;         // 真/假：有没有存到硬盘
类比：变量就是贴了标签的盒子。类型是"这个盒子只装什么"—— 整数盒、小数盒、文字盒、真假盒。

为什么要有类型：计算机需要知道"这个盒子占多大、能做什么运算"。count + 1 是加一，而 name + name 是文字接在一起 —— 它得先分得清。

2函数：把一段操作打包 
// 定义：做一件事 —— 算两个数的最大值
int maxOf(int a, int b)
{
    if (a > b) return a;
    return b;
}

// 使用：在别处直接叫它去做
int m = maxOf(3, 7);        // m 变成 7
类比：函数就像菜谱里的一条子步骤——"炒香葱姜"。你不需要每次都重抄一遍，写"炒香葱姜"就行。

好处有两个：① 同一个动作不用重复写；② 出了问题只改一个地方。

3类与对象：一张图 vs 一套房 
// 设计图：一张"图片"应该有什么
class Picture
{
public:
    string name;          // 属性：它的名字
    int    width;         // 属性：宽
    int    height;        // 属性：高

    void printSize()      // 方法：它能做的一件事
    {
        cout << name << " " << width << "x" << height << endl;
    }
};

// 按图造出一个具体的
Picture p;
p.name = "设计稿";
p.width = 800;
p.height = 600;
p.printSize();            // 输出：设计稿 800x600
类比：class 是户型图，Picture p; 是照图盖出的一套房子。图纸只有一张，房子可以盖很多套，而且每套的装修（属性值）不同。

为什么要把它们放在一起：因为"宽"和"高"只有跟"这张图"在一起才有意义。这就是"面向对象"想解决的事 —— 把相关的数据和对数据的操作捆在一块。

4判断与循环：让程序会"分开处理"和"重复做" 
// 判断：如果超过了上限，就压到上限
if (count > 50) {
    count = 50;
}

// 循环：把列表里每张图都打印一遍
for (int i = 0; i < pictures.size(); i++) {
    pictures[i].printSize();
}

// 更简洁的写法（效果一样）
for (const auto& p : pictures) {
    p.printSize();
}
类比：判断是"如果汤太咸就加水"；循环是"把每个盘子都检查一遍"。
5一组数据：用容器装很多东西 
#include <vector>

vector<Picture> pictures;     // 一个能装很多张图的"收纳架"
pictures.push_back(p);        // 放一张进去
cout << pictures.size();      // 里面现在有几张

// 想找某一张
if (!pictures.empty()) {
    pictures[0].printSize();  // 看第一张
}
类比：vector 是能随时加格子的收纳架（不像固定 10 格的药盒）。项目里"环上的一堆图"就是用这种东西装的。

这是你在 C++ 里最常用到的容器，先用熟它，别的容器以后再说。

6出错怎么办：别让一个小问题毁掉整个程序 
try
{
    savePicture(p, "D:/图片/1.png");   // 可能会失败：磁盘满、路径不存在
}
catch (const exception& e)
{
    cout << "保存失败了：" << e.what() << endl;   // 接住它，告诉用户
}
类比：try 是"我打算做这道菜"，catch 是"如果糊了就这样补救"。关键是：出岔子不等于整个程序崩掉。

项目里有大量这样的处理 —— 好的程序不是"永不失败"，而是"失败了也知道该怎么办、并且说清楚"。

4 · 五个能直接学走的故事

这些都是这个项目开发过程中真实发生的事。你不需要会写代码，也能从里面学到东西 —— 而且这些道理换任何语言都一样。

1「先量一量，再动手」—— 猜了三次都没对

项目里有个动画很卡。开发者凭经验猜：可能是"每帧画了太多东西"，于是改了一处；还是卡，又猜了第二个原因，改了第二处；第三次还是卡。

后来他决定先测量：给程序加上计时，看每一帧到底花在哪。结果发现 ——

  • 他以为的"元凶"，实测只占 0.3 毫秒（几乎可以忽略）；
  • 真正的大头在别处，占了 22 毫秒；
  • 再往下细分，真凶是某一处画文字的方式，在一个大画布上要 9 毫秒，而在小画布上只要 0.4 毫秒 —— 相差 21 倍。
能学走的：遇到"为什么这么慢"，先量，再改。凭感觉猜，往往改半天改错地方。
这条不只对编程有用 —— 修电脑、找东西、排查问题，都是同一个道理。
2「说好一起做的事，两边的标准得一样」

项目要把一段文字画在图片上，需要先问"这段字有多宽"，好给它留出位置。开发者用了一种方式去量，却用了另一种方式去画 —— 结果量出来 100 像素，实际画出来 118 像素，字的右半边被裁掉了。

同一个错误，他在项目里犯了四次（问宽度时用的字体不同、算的方式不同、对齐的基准不同……）。

类比：你要裁一块布，先用市尺量，却拿英寸的尺子去剪 —— 长度一定对不上。
量的时候用哪把尺，裁的时候就得用哪把。
能学走的：很多问题不是"做错了"，而是"两边的约定不一致"。
更好的做法是：把这四件事打包成一个函数，让别人不可能写错 —— 好的设计能让错误压根发生不了。
3「复制」和「移动」不是一回事

用户把一张图从环上拖到聊天窗口，图就发出去了。但开发者发现：拖完之后，环上那张图也没了，想再发给别人就没有了。

原因：这个"拖"在系统里是复制的意思（对方拿到的是副本），但代码却在成功之后把原件删了 —— 把"复制"当成了"移动"。

能学走的：写代码前先问自己一句："这个动作是复制、还是移动？谁拥有这份数据？"
想清楚再写，比写完再找问题便宜得多。而 C++ 里"复制"和"移动"是语言专门要区分的事 —— 你以后会学到。
4「用的时候先记账，走的时候要还账」—— 嵌套时最容易丢

项目有个"总显示在最前面"的功能。打开设置窗口时，主窗口要让到后面去；关掉设置，主窗口再回到最前面。

原来的做法：让位之前先记住"我原本在最前面"，结束时恢复成记住的那个值。

看起来完全正确，但出问题了：如果"让位"期间又发生了一次让位（比如截图时又打开了设置），恢复出来的就是"后面的状态"，于是主窗口永远回不到最前面了。

正确做法：用计数 —— 第一个进来的人负责记住原状态，最后一个离开的人负责恢复，中间的人只负责把数字加一减一。
这个思路到处都在用：图书馆借书（第一个借的人开门、最后一个走的人关灯）、共享单车、餐厅的最后一位客人负责让服务员收桌……
在编程里，内存管理、文件占用、数据库连接，用的都是同一套思路。
5「中文排得好好的，换成英文就挤爆了」

项目原本只有中文界面。想加英文版时发现：所有文字都被裁掉了、互相压在一起。

因为当初排版时是按"中文字数"估的宽度 —— 而同一句话，英文往往长得多。

类比：你按"中文 8 个字"给标签留了位置，换成 "Screenshots will appear here"（30 个字符）自然放不下。
能学走的：① 宽度要实际量，不能靠数个数猜；② 做界面时一开始就用最长的语言试一遍；③ 放不下的时候，正确做法是截断加省略号，而不是压到别的控件上。

5 · 给你的练习路线

每个练习都是小而完整的，做完能跑、能看到结果。按顺序来，不要跳。

#练习你会学到
1改一改 Hello World：换文字、打印多行、让它问你的名字再打招呼怎么编译运行、变量、输入输出
2算一算：输入两个数，输出和、差、平均值类型、运算、输入输出格式
3判断与循环：猜数字游戏（程序想一个数，你猜，它说"大了/小了"）条件判断、循环、随机数
4写自己的函数：把猜数字里"比较大小"单独写成一个函数函数、参数、返回值
5用容器存多条：一个能加人、能列出全部人的通讯录vector、遍历、增删
6自己定义类：把"联系人"做成一个类（姓名 + 电话 + 一个"打印自己"的方法）类、对象、属性、方法
7让它记得住：通讯录存到文件，下次打开还在文件读写、出错处理
8加一个"撤销删除"：删掉的人能恢复数据结构、状态管理（对应故事 4）
三条建议：
① 卡住超过半小时就问人 / 问 AI —— 不是偷懒，是避免把时间浪费在环境问题上（环境问题最耗人，而且学不到编程本身）；
② 报错信息一定要读 —— 它会告诉你第几行、什么问题，读懂了八成能自己修；
③ 每个练习都自己敲一遍，不要复制粘贴 —— 手敲的过程里你会不自觉地注意到细节。

6 · 初学 C++ 最容易走的四个弯路

1一上来就死磕语法书

语法书是"参考书"，不是"教材"。正确用法：先动手写小程序，遇到不会的再回头查。
一口气读完语法，你会发现"都看过了但什么也写不出来"。

2太早去碰指针和内存

这两个是 C++ 里最容易劝退的部分，但它们不是入门必须的。
先用标准库（string、vector、智能指针）把程序写起来 —— 这些工具已经帮你把内存管好了。等你写到"为什么这里要加个 &"的时候，自然会想弄明白，那时候再学会轻松得多。

3不看编译器的警告

C++ 的编译器会提示很多"虽然能编译，但很可能有问题"的地方。把警告当错误看（编译时加 -Wall -Wextra），能帮你躲掉一大堆将来会抓狂的问题。

这条其实对应故事 1 的道理：让工具先告诉你问题，而不是等程序出错才发现。
4以为"能跑"就等于"对"

有些错误不会立刻让程序崩溃，而是换个电脑、多跑一会儿、数据多一点才出问题。
所以：多写几个测试用例（比如"输入 0 会怎样""输入很大的数会怎样"），比"跑一次成功了"可靠得多。

这也是编程和"把题目做对"最大的区别：对错不是老师判的，是各种情况试出来的。

这个项目叫 SnapWheel（快照轮环），Windows 截图工具，单个程序文件、不装任何东西就能跑，界面全是代码画出来的。
本册由项目作者整理 —— 目的是让刚开始学编程的人也能从真实项目里学到东西：先学会"怎么写、怎么查、怎么验证"，语法可以慢慢补。
